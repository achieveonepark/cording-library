コアコンセプト

トリガー・条件・効果とドメイン非依存のデータモデル。

掛け算を足し算へ

ドメインごとに専用システム（SkillSystem、MonsterSystem、…）を作ると、 도메인 × 동작 マトリクスを毎回埋めなければなりません。AchReactive は動作プールをすべてのドメインで 共有させ、これを 도메인 + 동작 に変えます。

  • 新しいドメインの追加 → データクラス1個（システムコード0）
  • 既存の動作の再利用 → コード0、データのみ
  • 本当に新しい動作 → 関数1個、以降はすべてのドメインが共有

4つのレイヤー

上の2つのレイヤーはパッケージが提供し、変わりません。下の2つのレイヤーだけを埋めれば済みます。

リアクション = トリガー → 条件 → 効果

すべてのドメインは同じ言語で表現されます。

ドメインが異なっても形は同じです。

add_modifier は、スキルが使おうがアイテムが使おうが同じコード一つです。

統合境界

ゲームは2つのインターフェイスだけを実装します。

  • IEntity — Id, Position, Stats（StatSheet）, IsAlive
  • IWorld — Spawn, Collect

effect/condition は ReactionContext を通じて Source/Target/Targets/World にアクセスします。

typeof を使わない

複数のドメインを束ねる際に、Dictionary<Type, object> のような型キーのサービスロケーターを使いません。 各 DataBase<T> を明示的に保持し、クロスドメイン参照が必要な effect は 手動登録 + クロージャキャプチャで解決します。

はじめに

AchReactive のインストールから最初のリアクション実行まで。

データとソース

IData、DataBase、そして JSON・CSV・カスタムローダー。
