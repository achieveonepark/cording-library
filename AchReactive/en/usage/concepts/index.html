Core concepts

Triggers, conditions, effects, and the domain-agnostic data model.

Multiplication into addition

Building a dedicated system for each domain (SkillSystem, MonsterSystem, …) means filling in the domain × behavior matrix every time. AchReactive makes the behavior pool shared by all domains, turning this into domain + behavior.

  • Adding a new domain → 1 data class (0 system code)
  • Reusing an existing behavior → 0 code, data only
  • A genuinely new behavior → 1 function, then shared by all domains

The four layers

The top two layers are provided by the package and don't change. You only fill in the bottom two layers.

Reaction = trigger → condition → effect

Every domain is expressed in the same language.

The shape is identical even across different domains.

add_modifier is one and the same code whether a skill or an item uses it.

Integration boundary

The game only implements two interfaces.

  • IEntity — Id, Position, Stats (StatSheet), IsAlive
  • IWorld — Spawn, Collect

Effects/conditions access Source/Target/Targets/World through the ReactionContext.

We don't use typeof

When grouping multiple domains, we don't use a type-keyed service locator like Dictionary<Type, object>. Each DataBase<T> is held explicitly, and effects that need cross-domain references are solved with manual registration + closure capture.
