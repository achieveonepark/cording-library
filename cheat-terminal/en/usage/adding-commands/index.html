Usage

Adding Commands

Commands are registered explicitly with RegisterCommand(...). There is no automatic scan, and execution uses a CommandContext delegate instead of reflection invocation.

Usage string rules — usage decides how the cheat runs in the cheat HUD. Write no brackets when the command takes no arguments (god), <amount> for required arguments and [amount] for optional ones. The HUD creates separate parameter fields and a Run button. You do not need to type the command name. → Cheat HUD

Basic registration

Run gold 100000 or god in the console. help Cheats lists commands in that category with descriptions.

Static commands

Static methods are not collected automatically. Register them explicitly when you want them available.

Register them with:

Arguments

Read arguments from CommandContext.

  • ctx.Args: raw argument list
  • ctx.Has(index): whether an argument exists
  • ctx.GetString/GetInt/GetFloat/GetBool: fallback-based convenience getters
  • For strict validation, use TryParse(..., CultureInfo.InvariantCulture, ...) directly.

Adding completion candidates

You can attach command-specific suggestions at registration time.

Usage tokens like <easy|normal|hard> are also cached as default keyword suggestions.

Registering data tables

Registered tables appear in the data command, input suggestions, and the Data tab.

Writing output

Use CommandContext.Output for leveled output.

Advanced: ITerminalModule

Who is this for?

Use modules when you want to ship a reusable set of related commands.

For in-game cheat and debug commands, RegisterCommand(...) is usually enough.

Implement ITerminalModule and install it once with InstallModule().
