﻿# Ach — Shared Variables & Events

A system for sharing values and signals through ScriptableObject assets, so components can communicate without referencing each other directly.

Turn player health into a PlayerHP asset file, and the health bar UI, hit sound, and game-over manager can all watch the same asset. No inspector wires between them — when the value changes, everything stays in sync automatically.

Why use it?

Five building blocks

BlockOne-linerExample class
VariableAn asset holding a single valueIntVariable, FloatVariable
EventA signal asset carrying a valueIntEvent, VoidEvent
ListenerComponent that turns an event into a UnityEventIntEventListener
ReferenceToggle between a constant and a variable asset in the inspectorIntReference
CollectionA runtime-shared list assetGameObjectCollection

Built-in types: Int / Float / Bool / String / Vector2 / Vector3 / Color / GameObject (plus signal-only Void).

Create assets with right-click

In the Project view, right-click → Create → AchUtils → Ach.

Listeners are components — Add Component → AchUtils → Ach → Int Event Listener.

Quick start

1. Variable — share a value as an asset

Create PlayerHP via Create → AchUtils/Ach/Variables/Int Variable.

Player and HealthBar know nothing about each other — they connect through the PlayerHP asset.

2. Event — send a signal

Use a Void Event for value-less notifications, or a typed event to carry data.

3. Listener — wire reactions without code

Add AchUtils/Ach/Int Event Listener to the reacting object, then in the inspector drag onGoldChanged into Event and your method into Response. Designers can hook up sounds and effects without writing code.

4. Reference — switch between constant and variable

Pick whether a value is a hard-coded constant or a shared variable asset with one checkbox.

Prototype fast with constants, then share one variable asset across many places during balancing — without touching code.

5. Collection — share a runtime list

Create AliveEnemies via Create → AchUtils/Ach/Collections/GameObject Collection.

API

AchVariable<T>

AchEvent<T> / VoidEvent

AchReference<T, TVariable>

AchCollection<T>

Editor conveniences

  • Variable inspector — shows the live value during play, with a Reset To Initial Value button.
  • VoidEvent inspector — a Raise button during play lets you fire the event manually to test listener wiring.
  • Auto reset — variables and collections revert to their initial/empty state when entering play mode, so every run starts clean even with domain reload disabled.

Adding a new type

Need a value beyond the built-ins (e.g. Quaternion)? Just write one-line subclasses.

When to use it

It shines when you need to share values or signals across scene and prefab boundaries. For a value used only inside a single GameObject, a plain field is simpler.
